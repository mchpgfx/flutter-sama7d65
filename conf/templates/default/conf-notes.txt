Common targets for this configuration:

    mchp-flutter-gallery-image  Boots straight into the Flutter demo menu (gallery /
                               material-3, USER button returns to the menu)
    mchp-flutter-bench-image   Flutter (Skia CPU -> DRM) + benchmark and demo apps
    mchp-graphics-image        Microchip stock EGT image (known-good fallback)
    mchp-gles-probe-image      Mesa software-GLES probes (historical baseline)
    mchp-headless-image        No graphics stack

MACHINE defaults to sama7d65-curiosity-sd.

Running a Flutter app on the target:

    homescreen -b /usr/share/flutter/<app>/<version>/release

IVI_SW_SINK=drm-dumb and IVI_SW_DRM_FORMAT=rgb565 must be set. Without IVI_SW_SINK
the software backend discards every frame and the display stays blank with no error.
On mchp-flutter-bench-image they come from /etc/profile.d/ivi-homescreen.sh, which
covers login shells ONLY - systemd services do not read profile.d, which is why
flutter-demo-launcher exports them itself.
